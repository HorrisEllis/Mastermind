# TRIAGE — AssociativeLattice · resonance-v2 · resonance-webapp-stack · spatial_v2

Audited 2026-08-12 at MASTERMIND v0.1.14. 279 files across four archives
plus `spacial-docs.md` (1,973 lines).

**The headline: two of these are not MASTERMIND.** Resonance is a social
platform. Spatial is "an operating system for the space between people."
Both are products in their own right with their own specs and their own
audiences. Treating them as parts bins would damage them and bloat this.

What they share with MASTERMIND is *substrate* — and the substrate is
genuinely good and genuinely reusable.

---

| Archive | What it is | Verdict |

## Take these three, now

### 1. `@spatial/math` — zero-dependency primitives

Its own header states the case: *"Previously duplicated in drift-engine,
codec.js, codec-topology, sigma, text-module, pat-from-pcm,
attractor-landscape, resonance/fingerprint, nexus/identity."*

Nine copies of the same statistics, found and consolidated. MASTERMIND
has its own duplication of exactly this kind — `VLRollingStats` in the
voice lattice, the sigma logic in the ALK modules, and the new pitch
module all compute mean/variance independently.

**Highest-leverage single import in the whole haul**, because it is pure,
tested, dependency-free, and it deletes code rather than adding it.

### 2. `@spatial/idl` — the formal relational IDL

TypeScript definitions for `IntimacyVector`, `OscillationModel`,
`DriftModel`, `ResonanceResult`. Named axes with declared semantics.

This is **the closest thing in any archive to a P1 node envelope**. Not
because MASTERMIND needs intimacy vectors — it does not — but because it
demonstrates the shape: a formal, versioned, typed schema layer that
runtime implementations conform to, kept separate from any runtime.
`docs/NODE.spec.md` should be written in this style.

### 3. `@spatial/sigma` — entropy, slope, trajectory, regimes

`classify()` with named `REGIMES` and `DOMINANT_CAUSES`. MASTERMIND's
voice-lattice engine already has `vleSlopeEngine` and
`vleStabilityEngine` doing a subset of this less completely. Sigma is
the finished version of the same idea.

## Take the discipline, not the code

`resonance-v2` has `tests/unit/*` per engine plus
`tests/integration/full-pipeline.test.js`, and a `docs/LIVING.md`
alongside `docs/SPEC.md`.

The unit/integration split is better than MASTERMIND's flat `tests/`
directory. Twelve suites in one folder is already hard to navigate, and
the distinction between "this function is correct" and "these parts work
together" is worth making structural.

---

## Do NOT take

**`resonance-webapp-stack`.** Eight full HTML pages of a different
product's front end. Nothing here transfers.

**`@spatial/forge`** — "behavioral pattern compiler: observed patterns →
executable code. The system writes itself from what it sees." Interesting,
and a code generator driven by inferred behavioural patterns is a large
new trust surface. It belongs to Spatial, where it has a spec. It should
not arrive here as a side effect of a salvage pass.

**Anything downstream of the ALK expression/suppression stack** until the
measurement audit is done. `suppression-score.js`, `latent-model.js` and
`signal-topology.js` appear in every one of these archives, and they
inherit the codec-v2 problem: real-sounding labels over computations that
may not support them. The pitch defect was proven, not suspected — the
same audit has not yet been run on suppression or valence.
